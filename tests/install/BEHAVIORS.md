# install.sh — behaviour table

Rows R1–R9 predate this table: each lives in its test's docstring in `test_install.py`, which starts with the row.
R1.4 and R1.5 gained the `rw-git` link and its note line with R10, and R1.4 the `rw-git: interpreter` line with U58.
R3 changed when the earlier-clone exception landed: a live link that resolves outside this clone is refused unless it
resolves into an earlier robowright clone (R3.1, R3.4, R3.7–R3.13), and R3.2, R3.5 and R4.8 point into that earlier
clone. R3.2, R3.3, R3.6 and R3.8 gained the `(was <old>)` suffix when a retarget began printing the target it replaced,
and R3.14–R3.16 were added with it.

## rw-git on the Owner's PATH (R10)

| # | Rule | Given | When | Then | Expected value from |
|---|---|---|---|---|---|
| R10.1 | `rw-git` is a file, mode 0755, not a link: a `#!/bin/sh -p` wrapper that execs the clone's `rw_git.py` under `env -i`, with the interpreter and HOME fixed at install | a fresh scratch HOME | `install.sh` | exit 0; `~/.local/bin/rw-git` a regular file, mode 0755, exactly `#!/bin/sh -p` then `exec /usr/bin/env -i PATH=/usr/bin:/bin HOME='<home>' '<python3>' -I '<clone>/skills/robowright/scripts/rw_git.py' "$@"`, `<python3>` the install's `python3`'s `sys.executable` | U52b F1: "written as a file, mode 0755, not linked"; plain `#!/bin/sh` is injectable through `SHELLOPTS`/`PS4` (verifier, ran) |
| R10.2 | the install names the folder and why no session may write it | a fresh scratch HOME | `install.sh` | stdout holds `wrote <bin>/rw-git`, then `rw-git: interpreter <python3>` (R10.1's `<python3>`), and `rw-git: written into <bin>. Sessions run rw-git outside their sandbox, so no session may write <bin>, or any folder before it on PATH` | U46 bound 6; F1: "the install note still says no session may write `~/.local/bin` or a folder before it on `PATH`"; U58 D2: the Owner sees which interpreter the wrapper runs |
| R10.3 | a link from an old install, this clone's or another's, is replaced by the wrapper | `~/.local/bin/rw-git` a link to this clone's `rw_git.py`; then one into another checkout | `install.sh` | exit 0 each; the path is the wrapper file, and the other checkout's file unchanged | F1: "R10.3's successor" |
| R10.4 | a regular file that is not this clone's wrapper is refused, and nothing is linked | a regular file `mine`; then another clone's wrapper | `install.sh` | exit 1; stderr names the path; the file unchanged; no skill linked | F1: "a regular file that is not this clone's wrapper is refused and left unchanged (R10.4)" |
| R10.5 | a linked bin folder is refused, and nothing is linked | `~/.local/bin` is a link to another folder | `install.sh` | exit 1; stderr names `~/.local/bin`; the other folder stays empty; no skill linked | R9's refusal of a linked `skills/` |
| R10.6 | uninstall removes its own wrapper and keeps another clone's, and another's link | an install; then another clone's wrapper at the same path; then a link elsewhere | `install.sh --uninstall`, each time | `removed <bin>/rw-git` the first time; the other wrapper and the link kept | F1: "removes the file when its `exec` line names this clone (`is_inside_clone` on that path), and keeps another clone's" |
| R10.7 | a clone with no `rw_git.py` makes no bin folder | a synthetic clone with skills and agents only | `install.sh` | no `~/.local` | design: a dangling `rw-git` on PATH |
| R10.8 | this clone's wrapper is rewritten in place when it differs | this clone's wrapper naming another interpreter | `install.sh` | exit 0; `wrote <bin>/rw-git`; the file is R10.1's | F1: "a wrapper this clone wrote is rewritten in place (idempotent)"; R2 covers the rerun that prints nothing |
| R10.9 | the wrapper runs `rw_git.py` with a scrubbed environment, isolated, its arguments passed through | a clone whose `rw_git.py` is a stub printing its environment, `sys.flags.isolated` and argv; installed | the wrapper run with `FOO`, `SHELLOPTS=xtrace`, `PS4`, `PYTHONPATH` and `ENV` set, args `--help` and `a b` | exit 0; the environment is `PATH=/usr/bin:/bin` and `HOME=<home>` only; isolated; argv `--help`, `a b`; no trace on stderr | F2: "observed through a stub `rw_git.py` that prints `os.environ`" |
| R10.10 | a virtual environment's interpreter is refused before anything is linked | a venv's `bin/` first on `PATH`, its `python3` reporting `sys.prefix != sys.base_prefix` | `install.sh` | exit 1; stderr names the venv's `python3` path and says a virtual environment's interpreter is refused; no `rw-git`, no skill or agent linked | U58 D1: a venv's `.pth` files run under `-I`, so the wrapper would run code the venv's folder chooses, as the Owner |
| R10.11 | a `python3` that prints no interpreter path is refused before anything is linked | a `python3` first on `PATH` that prints nothing and exits 1 | `install.sh` | exit 1; stderr says python3 printed no interpreter path; no `rw-git`, no skill or agent linked | U58 D1: the old exit came after every link, a half install |
