# rw-git — behaviour table

`skills/robowright/scripts/rw_git.py`, run as `rw-git`: the one program a sandboxed session uses to write a
repository's git directory. It runs outside the sandbox, as the Owner, so every row below is about what it refuses
to do, or what it keeps git from running.

Every test runs against a scratch `HOME` whose `.gitconfig` names a made-up identity and whose
`.claude/robowright/launch.json` lists one scratch repository `sample`, with a sessions root and a projects root
beside it. The repository has a linked worktree at `<repo>/.worktrees/sample-001-x` on `robowright/sample-001-x`.
A test that needs a remote patches the module's protocol allowlist in a child process (`file`, `http`), since a
scratch remote cannot be `ssh` or `https`; the shipped list is checked on its own (P1).

A marker test plants the program as a script that touches `<scratch>/markers/<key>` and exits 1, so a key that runs
fails loudly as well as leaving its marker.

Source of every expected value: the brief (`briefings/git-broker.md`, bound 1, "Verify"), the scope
(`design/u46/SCOPE.md`, "The design"), and `git help config` for which keys name a program.

## A person's daily git (U49)

Source of every expected value: `REPLAN-2026-10-17-endgame.md` → §U49, decisions D1–D4 and requirements R1–R9 (the
Owner's grilling, 2026-10-17), and `git help reset`, `git help rebase`, `git help commit` for what git itself does
(P5). The runner names `desk` as a `desktop_roots` entry. Every row runs with fsmonitor, pager, editor, external
